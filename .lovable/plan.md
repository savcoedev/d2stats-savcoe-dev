## Goal
Add a committed `.env.example` documenting required env vars, and ensure `.env` is git-ignored.

## Changes

### 1. Create `.env.example` (project root)
Mirror the auto-managed `.env` keys with safe placeholder values so contributors know what to configure:

```
VITE_SUPABASE_PROJECT_ID="your-supabase-project-id"
VITE_SUPABASE_PUBLISHABLE_KEY="your-supabase-publishable-anon-key"
VITE_SUPABASE_URL="https://your-project-ref.supabase.co"
```

Includes a top comment explaining:
- These are Vite client-side vars (publishable/anon only — never put secrets here).
- On Lovable, `.env` is auto-generated by Lovable Cloud; this file is for local/forked setups.
- Server-side secrets (Steam API key, etc.) belong in Supabase Edge Function secrets, not here.

### 2. Update `.gitignore`
Append an explicit env-files block so `.env` (and variants) are never committed, while keeping `.env.example` tracked:

```
# Local env files
.env
.env.local
.env.*.local
!.env.example
```

The existing `*.local` line already covers `.env.local`, but the explicit block makes intent obvious and adds the `.env.example` allow-rule.

## Notes
- No code/runtime changes — purely repo hygiene.
- The real `.env` is managed by Lovable Cloud and will not be touched.
